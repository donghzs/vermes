# Vermes 2.5 · 前端显形事件契约（草案）

> **状态**：E-P0-5 草案，冻结后作为 U-P0（聊天时间线/状态灯/交付卡等）的**硬前置**  
> **原则**：**先 schema 后 UI**；后端可增量填充；**缺信号时 UI 显示「暂无信号」**，禁止编造进度或 ✅  
> **日期**：2026-09-18 · 分支 `fix/harness-circuit-max-attempts`

---

## 0. 传输层约定

| 项 | 约定 |
|----|------|
| 主通道 | 现有聊天 **SSE**（`chat.py` tool_progress / status / evolution 事件） |
| 扩展方式 | 在既有事件 JSON 上增加**可选**字段；老前端忽略新字段仍可工作 |
| 版本 | 每个事件体含 `"contract": "v2.5-s1"`（或全局 `header.contract`） |
| 缺信号 | 字段缺失 / `null` → UI **「暂无信号」**，不得默认为成功 |
| fail-open | 后端子系统失败 → `harness_obs` 计数事件；**不**把失败伪装成完成 |

---

## 1. 事件类型

### 1.1 `tool_step` — 工具执行步

对应 `tool_progress_callback` 的 `tool.started` / `tool.completed` 扩展。

```json
{
  "contract": "v2.5-s1",
  "type": "tool_step",
  "tool": "scholarforge_write",
  "tool_call_id": "call_xxx",
  "phase": "started | completed | blocked | error",
  "ts": "2026-09-18T12:00:00Z",
  "duration_ms": 1234,
  "preview": "…",
  "artifacts": [{ "path": "…", "title": "…", "source": "write_file", "mime": "text/markdown" }],
  "harness": {
    "precheck": "ok | warning | blocked | unknown",
    "precheck_msg": null,
    "circuit_open": false,
    "retries_attempted": null,
    "max_attempts": null,
    "self_validator": "ok | fail | unavailable | unknown",
    "result_validator": "ok | warning | error | unknown",
    "outcome": "verified | unverified_tool | verify_failed | verifier_error | unknown",
    "outcome_reason": null,
    "failure_learning_hint": null
  }
}
```

| 字段 | 真源 | 缺省时 UI |
|------|------|-----------|
| `harness.precheck` | `tool_precheck.run_precheck` 结果 | 暂无信号 |
| `harness.max_attempts` / `retries_attempted` | `max_attempts_for` + `invoke_with_retry` | 不显示重试次数 |
| `harness.outcome` | `outcome_verifier` / `verify_fn`；无 verify_fn → `unverified_tool` | 灰点「未独立核验」 |
| `harness.*_validator` | self_validator / result_validator | 暂无信号 |

### 1.2 `harness_status` — 子系统可观测

对应 E-P0-2 `_harness_fail_log` / `get_harness_fail_counts()`。

**已接线（U-P0-1 最小信号源）**：`GET /api/harness/status`  
（`vermes_cli/blueprints/chat.py` `harness_status`；ChatHeader 轮询消费）

```json
{
  "contract": "v2.5-s1",
  "type": "harness_status",
  "ok": true,
  "fail_counts": { "circuit_breaker": 2, "self_validator": 1 },
  "fail_total": 3,
  "degraded": true,
  "signal": "http_poll"
}
```

SSE 推送（后续）示例：

```json
{
  "contract": "v2.5-s1",
  "type": "harness_status",
  "ts": "…",
  "component": "circuit_breaker",
  "event": "failed",
  "tool": "web_search",
  "error": "…message…",
  "counts": { "circuit_breaker": 2 }
}
```

- UI：通知中心角标 + 状态灯黄/红；**不**把 harness 自身异常显示为工具成功。  
- `signal=unavailable` 或缺字段 → **暂无信号**（灰），禁止假绿灯。

### 1.3 `deliverable` — 交付摘要

```json
{
  "contract": "v2.5-s1",
  "type": "deliverable",
  "ts": "…",
  "session_id": "…",
  "task_id": "…",
  "items": [
    {
      "kind": "file | project_section | export | db_row | unknown",
      "path": null,
      "project_id": null,
      "project_title": null,
      "section_key": null,
      "bytes": null,
      "chars": null,
      "title": "项目 #52「幼小衔接研究」abstract",
      "verified": "verified | unverified_tool | verify_failed | unknown",
      "url": null
    }
  ],
  "summary": "写入 1 个章节到项目 #52",
  "source_tools": ["scholarforge_write"]
}
```

| 字段 | 真源 |
|------|------|
| `items[].path` | `tool_executor._build_tool_artifacts` / write_file args |
| `project_*` | scholarforge `resolve_project_id` + 兜底显形提示 |
| `verified` | `compute_verified` / outcome_verifier |

### 1.4 `route` — 模型/Auto 路由

```json
{
  "contract": "v2.5-s1",
  "type": "route",
  "ts": "…",
  "requested_model": "auto:cost",
  "strategy": "cost | balanced | speed | none",
  "resolved": {
    "provider": "agnes",
    "model": "agnes-3.0-flash",
    "base_url": "https://…"
  },
  "candidates": 5,
  "token_usage": { "prompt": null, "completion": null, "total": null },
  "cost_estimate": null,
  "note": null
}
```

- 真源：`resolve_smart_route` log 行 `strategy -> pid/model`；usage 可后接 SSE token。  
- **2.5 范围**：有 `resolved` + `strategy` 即可展示；`cost_estimate` 可 null（P1）。

### 1.5 `memory_event` — 压缩 / 记忆

```json
{
  "contract": "v2.5-s1",
  "type": "memory_event",
  "ts": "…",
  "kind": "compressing | compressed | compress_skipped | compress_failed | memory_indexed | flag_opened | skill_curated",
  "message": "🗜️ 正在压缩上下文……",
  "detail": {
    "tokens_before": null,
    "mode": "standard | deep | …",
    "preserved_decisions": null,
    "preserved_preferences": null,
    "layer": null,
    "flag_id": null,
    "skill": null
  }
}
```

- `kind=compressing` 对齐现有 `COMPACTION_STATUS_MARKER` / `kind="compacting"`。  
- **禁止**字段名暗示「L1/L2/L3 压缩分层」或「dream」（文案纠偏）。

### 1.6 `harness_obs` 与 UI 映射（摘要）

| 后端信号 | UI |
|----------|-----|
| tool_step.precheck=blocked | 红灯 + 原因 |
| tool_step.outcome=verified | 绿灯 |
| tool_step.outcome=unverified_tool | 灰灯「未独立核验」 |
| harness_status.failed | 黄/红角标 + 通知 |
| route | 会话头「Agnes 3.0 · 经济」 |
| deliverable | 任务结束交付卡 |
| memory_event | 生命周期条 |

## 2. 后端最小接入点（增量，不阻塞 UX 开工）

| 步骤 | 落点 | 产出字段 |
|------|------|----------|
| S1-a | `tool_executor` 在 `_harness_fail_log` 处 optional callback | `harness_status` |
| S1-b | tool_progress completed 附带 harness 字典（能取到多少填多少） | `tool_step.harness` |
| S1-c | chat 路径在 `resolve_smart_route` 后发 `route` 事件 | `route` |
| S1-d | `_emit_status` 压缩文案包一层 `memory_event` | `memory_event` |
| S1-e | scholarforge write 成功后发 `deliverable`（项目+章节） | `deliverable` |

任一步未完成时：前端对**缺失 type** 不渲染或显示「暂无信号」。

---

## 3. 验收

1. 文档与 JSON 示例可被前端 mock 消费。  
2. 无后端新事件时，UI 不崩溃、不假绿灯。  
3. 文案不含「L1/L2/L3 压缩」「自动 dream」等未实现宣称。  
4. `harness_status.counts` 与 `get_harness_fail_counts()` 语义一致。
